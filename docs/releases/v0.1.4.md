# MoonlightOS v0.1.4

MoonlightOS v0.1.4 improves the USB support-file export experience and makes export failures visible instead of leaving the user unsure whether anything happened.

## Improvements

- Adds a dedicated full-screen support-export progress view in Settings.
- Adds an animated terminal spinner and indeterminate ASCII progress bar while the support bundle is being collected and written.
- Shows the selected USB destination and elapsed export time.
- Keeps the export UI active until MoonlightOS receives a definite success, failure, or timeout result.
- Reports explicit failures when no writable removable USB drive is available, the request cannot be submitted, the exporter service does not start, the exporter reports an error, or the operation exceeds its timeout.
- Shows the exact saved archive path after a successful export.
- Adds regression coverage for support-export progress rendering, success, exporter failure, missing USB media, and service-start failure.

The support archive continues to use the existing hardened exporter: removable-media identity is revalidated before writing, sensitive values are redacted, the archive manifest is verified, the copy is written atomically, a SHA-256 sidecar is created, and the destination is synced before completion is reported.

Moonlight Qt remains pinned at 6.1.0 and runs through XWayland with `QT_QPA_PLATFORM=xcb`. chiaki-ng remains pinned at 1.10.0 and uses native Wayland. Firefox ESR remains Debian-packaged and native Wayland.

## Validation scope

The source regression suite, ISO build, UEFI QEMU boot test, and automated Moonlight/chiaki-ng/Firefox startup smoke test run in GitHub Actions before the release workflow is allowed to publish the ISO. Physical USB-media behavior and the visual progress screen should still be qualified on target hardware.

Verify the downloaded image before writing it:

```bash
sha256sum --check moonlightos-0.1.4-amd64.iso.sha256
```
