# MoonlightOS v0.1.6

MoonlightOS v0.1.6 adds native, controller-friendly Bluetooth management while
keeping the launcher in the same curses session.

## Bluetooth

- Settings now includes Bluetooth power, discovery, pairing, connection,
  disconnection, and forget-device controls.
- Pairing supports confirmation codes, displayed passkeys, and controller-first
  numeric PIN/passkey entry.
- A restricted per-user service talks to BlueZ over the system D-Bus through a
  fixed local JSON protocol. Scanning and pairing are cancellable and bounded.
- Paired controllers appear through the existing evdev input path without a
  launcher restart.
- Bluetooth audio devices can be selected explicitly through PipeWire; HDMI/DP
  audio is not replaced automatically.
- Diagnostics include sanitized adapter and connection state. BlueZ pairing
  secrets are explicitly inaccessible to the support exporter.

## Reliability and validation

- Missing adapters, adapter removal, BlueZ restarts, and control-service failure
  return safely to Settings without restarting Cage, Foot, or the launcher.
- Source tests cover the UI, local protocol, BlueZ object state, pairing-agent
  callbacks, command validation, operation conflicts, and privacy boundary.
- The ISO workflow builds the image, boots it under UEFI QEMU, verifies clean
  no-adapter behavior, restarts both Bluetooth services without changing the
  launcher PID or restart count, and then launches Moonlight, chiaki-ng, and
  Firefox.

Physical Bluetooth radio, controller, keyboard, and audio tests remain required
on compatible hardware and are not claimed by the automated test suite.
