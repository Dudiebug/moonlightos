# MoonlightOS v0.1.2

MoonlightOS v0.1.2 adds controller-friendly display settings and a privacy-aware
support-file exporter to the existing terminal appliance.

## Highlights

- Full-screen black-and-white curses Settings page under Cage and Foot
- Resolution and refresh selectors populated only from modes advertised by
  wlroots through `wlr-randr`
- `wlr-randr --dryrun` validation, 15-second preview, controller/keyboard
  confirmation, and automatic rollback
- Confirmed display mode persistence tied to both connector and encoded display
  identity, with safe fallback to the compositor default when hardware changes
- Controller-navigable removable-media selection for support exports
- Root systemd path/service exporter with concurrency control and inaccessible
  application, browser, pairing, and Tailscale private-state directories
- Redacted hardware, graphics, audio, network, service, journal, and MoonlightOS logs
- Hidden-partial copy, archive validation, atomic rename, sync, and failure cleanup

Moonlight Qt remains pinned at 6.1.0 and runs through XWayland with
`QT_QPA_PLATFORM=xcb`. chiaki-ng remains pinned at 1.10.0 and uses native
Wayland. Firefox ESR remains Debian-packaged and native Wayland. Closing any
application returns to the launcher.

## Validation scope

Source tests and the UEFI QEMU application smoke test are automated. QEMU does
not prove display switching, controller hardware, Intel acceleration, physical
audio, streaming quality, or USB-media behavior on the target Dell OptiPlex.
Those items remain explicit physical qualification steps in
[`docs/TESTING.md`](../TESTING.md) until recorded on that hardware.
